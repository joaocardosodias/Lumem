## Falhas encontradas e correções

### 1. Remoção do arquivo antes do fechamento da leitura

Na primeira execução com PostgreSQL, os quatro subcasos da importação em lotes falharam com erro do Windows: o arquivo estava em uso quando o processamento tentava removê-lo. O status e a transação já haviam sido tratados, mas a finalização retornava `CleanupPendingError`.

Nos casos de uso de alarmes e manutenção, o `defer rc.Close()` estava no escopo de `ProcessJob`, sendo executado somente depois da tentativa de limpeza. Agora, o processamento transacional fica em um escopo que fecha o leitor **antes** de executar a limpeza do arquivo, inclusive nos caminhos de erro.

Arquivos alterados:

- `src/backend/internal/usecase/ingest_alarms_usecase.go`.
- `src/backend/internal/usecase/ingest_maintenance_usecase.go`.

O teste `src/backend/tests/integration/streaming_ingestion_test.go` também passou a conferir explicitamente que o arquivo temporário não existe após a finalização. Os quatro subcasos passaram no reteste, verificando tanto os dados no PostgreSQL quanto a limpeza do arquivo.

### 2. Preparação do teste de erro de arquivo temporário no S3

A primeira regressão de todos os pacotes encontrou falha em `TestS3StorageStoreTempFileError`: o teste configurava apenas `TMPDIR`, enquanto o Windows utiliza `TMP`/`TEMP`. Por isso, a operação conseguia criar o arquivo quando o teste esperava erro.

A fixture em `src/backend/internal/adapter/storage/s3_storage_test.go` agora configura as três variáveis para o mesmo diretório inexistente, usando `t.Setenv` para restauração automática. O adaptador S3 de produção não foi alterado. Esse teste usa uma API S3 simulada; sua aprovação não comprova acesso ao MinIO/S3 real.

## Reprodução

Executar em PowerShell com Docker iniciado e Go 1.26 disponível. Usar um nome de contêiner e uma porta livres. Os valores abaixo são credenciais exclusivas de teste local:

```powershell
docker run --detach --rm --name g04-rf-postgres-test `
  --env POSTGRES_USER=rf_test --env POSTGRES_PASSWORD=rf_local_only `
  --env POSTGRES_DB=rf_test --publish 127.0.0.1:55439:5432 `
  postgres:16-alpine@sha256:721873c34ceb9f8d8fc265984940dc982404c105f19ad51be9fdc5970a6080ea

docker exec g04-rf-postgres-test pg_isready -U rf_test -d rf_test
```

Aguardar `accepting connections`. Na pasta `src/backend`, executar:

```powershell
$previousTestDsn = $env:TEST_DATABASE_URL
try {
  $env:TEST_DATABASE_URL = 'postgres://rf_test:rf_local_only@127.0.0.1:55439/rf_test?sslmode=disable'
  go test -p 1 -count=1 -json ./... > postgres-full-results.json
  if ($LASTEXITCODE -ne 0) { throw 'A regressão falhou; consultar o arquivo de resultados.' }
} finally {
  $env:TEST_DATABASE_URL = $previousTestDsn
  docker stop g04-rf-postgres-test
}
```

Para reproduzir somente os cinco testes anteriores, trocar o comando Go por:

```sh
go test -p 1 -count=1 -json ./tests/integration ./cmd/api -run '^(TestPostgresRepositories|TestStreamingIngestionCommitsAllBatchesOrRollsBack|TestCheckDatabaseConnection_AndMigrations|TestRF07_PostgresActiveDoorSelection|TestRF10_PostgresIndicatorsAndInspectionDeduplication)$'
```

Usar um contêiner/banco novo para cada repetição completa. Os testes executam migrations e alteram registros; não utilizar banco compartilhado ou operacional. O código de saída e a ausência de eventos `skip` com campo `Test` devem ser conferidos, pois alguns testes antigos ainda ignoram indisponibilidade de banco.
