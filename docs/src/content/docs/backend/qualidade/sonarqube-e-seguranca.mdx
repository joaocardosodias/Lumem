## 2. Otimizações de manutenibilidade orientadas pelo SonarQube

Durante o ciclo de desenvolvimento, a análise estática contínua orientou melhorias essenciais de legibilidade e segurança:

### 2.1 Redução de Complexidade Cognitiva (Regra S3776)

A função `Config.Validate` acumulava validações aninhadas de ambiente, drivers de storage, portas HTTP, pools de banco de dados e credenciais de observabilidade, atingindo complexidade cognitiva acima do limite aceitável de 15.

A estrutura foi decomposta em funções auxiliares especializadas:

```go
func (c *Config) Validate() error {
	if err := c.validateProduction(); err != nil {
		return err
	}
	if err := c.validateStorage(); err != nil {
		return err
	}
	if err := c.validateTelemetry(); err != nil {
		return err
	}
	return nil
}
```

Cada função especializada passou a ter um escopo restrito e testável isoladamente, zerando os apontamentos da regra S3776.

### 2.2 Prevenção de `copylocks` em estruturas concorrentes

O `go vet` e o SonarQube apontavam risco de violação na cópia de estruturas contendo `sync.Mutex` em testes unitários paralelos. Quando uma struct que encapsula um mutex é passada por valor, seu estado interno de trava é copiado, o que invalida a sincronização entre goroutines e causa data races.

Todos os mocks e estruturas auxiliares concorrentes foram construídos com compartilhamento estrito por ponteiro (`*sync.Mutex` ou instâncias `&mockStruct{}`), eliminando completamente os alertas `copylocks`.

## 3. Segurança de contêiner e dependências

A segurança em tempo de compilação e empacotamento é garantida por duas ferramentas integradas à esteira:

### 3.1 Auditoria de vulnerabilidades em código Go (`govulncheck`)

O job de segurança executa `govulncheck ./...`, que analisa o Grafo de Chamadas (Call Graph) do binário compilado. Ao contrário de analisadores puramente estáticos que apenas leem o `go.mod`, o `govulncheck` verifica se as funções efetivamente vulneráveis de uma dependência são invocadas pelo código do backend.

### 3.2 Varredura de contêiner com Trivy

A imagem Docker é submetida a scan de vulnerabilidades pelo Trivy antes de ser publicada:

```bash
trivy image --exit-code 1 --severity HIGH,CRITICAL g04-backend-api:latest
trivy image --exit-code 1 --severity HIGH,CRITICAL g04-backend-worker:latest
```

**Diretrizes de endurecimento (hardening) da imagem:**
- **Compilação Estática:** `CGO_ENABLED=0` elimina dependências de bibliotecas dinâmicas C (`glibc`);
- **Stripping de Binário:** flags `-ldflags="-w -s"` removem símbolos de depuração e tabelas de símbolos, reduzindo o tamanho do binário e dificultando engenharia reversa;
- **Usuário não raiz (non-root):** a imagem cria e executa sob o usuário `appuser` com UID 10001, impedindo que um invasor obtenha privilégios de root no host caso ocorra escape de contêiner.

## 4. Modelo de ameaças simplificado (STRIDE)

O backend adota o framework STRIDE para mapear e mitigar os principais vetores de ataque:

| Categoria | Vetor de ataque potencial | Mitigação implementada no backend |
|---|---|---|
| **Spoofing (Falsificação)** | Falsificação de identidade de operadores | Tokens JWT assinados com HMAC-SHA256 e tempo de expiração curto; senhas com hash bcrypt custo 10 |
| **Tampering (Adulteração)** | Alteração de arquivos CSV/XLSX em trânsito | Cálculo de hash SHA-256 no recebimento; bucket S3 privado sem escrita anônima |
| **Repudiation (Repúdio)** | Operador nega ter importado planilha com dados errôneos | Tabela `file_uploads` armazena `user_id`, data/hora UTC, nome original e hash do arquivo |
| **Information Disclosure (Vazamento)** | Exposição de credenciais ou dados do metrô | Rota `/metrics` bloqueada no proxy; logs mascaram segredos; bucket S3 estritamente privado |
| **Denial of Service (DoS)** | Esgotamento de conexões com planilhas gigantes | Rate limiter configurável por IP (token bucket); CSV por linha; XLSX em arquivo temporário com limite de descompressão; ingestão em lotes de 500 registros |
| **Elevation of Privilege (Elevação)** | Escalonamento de privilégios no contêiner | Execução exclusiva sob usuário sem privilégios (`appuser` UID 10001) |
